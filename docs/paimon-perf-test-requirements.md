# Paimon 性能测试需求

## 一、测试目标
- **交付对象**：业务方
- **判定标准**：达到绝对值目标
  - 写入吞吐：≥ 2 万条/秒
  - 端到端延迟：≤ 3 分钟

## 二、运行环境
| 组件 | 版本/规格 |
|------|------|
| Flink | 1.19.2 |
| Paimon | 1.1 |
| Kafka | 2.x |
| 资源调度 | CDH YARN |
| Catalog | Hadoop catalog |
| 部署模式 | 离线环境（无外网，依赖需外网打包后搬运） |

## 三、资源清单
| 资源 | 容量 | 评估 |
|------|------|------|
| YARN | 130 核 | 充裕，支持单表压测 |
| HDFS | 10 TB | 可测 5-7 天持续写入 |
| Kafka | 1 TB | 够用（存储容量） |

## 四、测试数据特征
- **规模**：3000 万账户
- **表结构**：宽表（100 列）
- **主键**：有
- **更新模式**：高频更新，50% update（其余 insert）

## 五、测试范围（分阶段）
1. **阶段1 单表极限压测**（必做）— 建立性能基线、技术上限
2. **阶段2 生产模拟场景**（必做）— 用真实负载验证 SLA

> 阶段3（多表混合负载）已确认不做。

## 六、观测指标（四类）
1. **写入与入湖性能**：CDC/海量流数据写入总耗时、吞吐量、并发写入能力
2. **更新与删除效率**：LSM 引擎高频主键 Update/Delete 性能
3. **读取与查询性能**：配合 Flink，冷热数据点查、OLAP 查询的延迟与 QPS
4. **资源消耗与 Compaction 开销**：小文件合并的 CPU/内存消耗、存储空间利用率

## 七、已有基础设施
- Flink metrics 自动上报 → Kafka → StarRocks（表 `RDW_ODS_FLINK_METRICS`）
- 表侧 metadata 可入同一 Kafka 管道

## 八、当前缺口
| 缺口 | 解决方向 |
|------|---------|
| Paimon metadata 无法自动上报 | 独立采集器（Java，离线部署单 jar） |
| YARN/HDFS metrics 未采集 | 调 REST API 采集 |
| StarRocks 分析 SQL 未开发 | 瓶颈定位 + 基线对比 SQL |

## 九、技术选型约束
- **采集器语言**：Java（团队有能力 + 离线部署单 jar 简单）
- **排除 Python**：离线依赖传递复杂，部署成本高
