### 4.2 Compaction 批任务（crontab 每 5 分钟 paimon-compact）

> 真实形态（2026-08-06 现场核实）：合并不是流式常驻的 `compaction_job`，而是 crontab
> 每 5 分钟提交一次 BATCH 模式的 `paimon-compact`（paimon-flink-action compact），
> 跑完几十秒即退出。因批任务生命周期短于指标上报周期（3 分钟），compaction 作业侧指标
> （`metrics_compaction_job` 视图、health_flags 的 `compaction_flag`）在该形态下通常无数据，
> 合并是否生效以 Paimon `$snapshots` 的 COMPACT 提交为准。

- [ ] **crontab 条目存在且按 5 分钟周期触发**
  ```bash

  ```
  **预期**：存在类似 `*/5 * * * * ... paimon-compact ...` 的条目

- [ ] **cron 日志有每次运行记录与退出码**
  ```bash
  tail -n 50 <compact日志路径>   # crontab 条目里 >> 重定向的日志文件
  ```
  **预期**：每 5 分钟有一条运行记录，退出码为 0；退出码非 0 时按日志报错定位

- [ ] **YARN 上有 paimon-compact 应用历史**

  **预期**：存在 paimon-compact 应用记录，且随 5 分钟周期持续新增，最近批次

## ⚠️ 常见问题排查

### Q1：Kafka 指标未上报

**排查步骤**：
1. 检查采集器日志：`ERROR` / `Connection refused`
2. 验证 Kafka 连通性：`telnet ${KAFKA_HOST} 9092`
