# 前端编码指导

本文件在改动前端源码时加载，是前端编码指导，不是产品或合同权威。按你的前端目录/框架调整上面的 `fileMatchPattern`。

**权威关系（别接反）**：门面/展示原则与契约字段以**项目产品/门面文档**为准；当前实施增量以其 spec 的 requirements/design/tasks 为准（design 是落地来源，不是原则权威）；契约字段与端点边界以项目产品文档和后端实现为准，前端不定义后端没有的字段。本文件只补前端编码判断。

## 1. 门面红线（当前端是纯渲染门面时）

**若架构约定「判断在后端/服务层、前端只渲染」**（很多 To B 系统如此；若你的前端也承担判断，本节按实际归属调整），编码时禁止：

- 用字段组合在前端重新判断后端已给出的结论（等级、严重程度、分类、优先级、充分性）；
- 重排后端给定的结果顺序，或把内部域名当展示主结构骨架；
- 为契约缺字段补默认文本、占位值或推测值（应显示「未取得」并保留结构）；
- 在前端还原、扩大或重新解释后端已脱敏的内容，或在前端拼装对外交付物（导出走后端）；
- 从两个读接口对同一展示值各推一份，形成两个可能矛盾的来源。

判据：一个界面决定若改变**使用者对结果的结论**（隐藏、重排、补值、替后端判范围），就越线；若只改变**像素如何、何时出现**，是门面本职。

界面层判断是本职、不受上述限制：加载/成功/失败/空四态、是否可重试、下钻展开或折叠、输入格式的非阻断提示、焦点移动、响应式呈现。注意：输入校验只能是非阻断提示（业务是否合法由后端判定）；折叠是渐进披露，不能让后端已给的结果段事实上消失或改变顺序。

## 2. 组件与状态

- 组件表达界面与交互意图；网络访问集中在单一 apiClient，副作用只出现在事件处理、明确的同步 Effect 或请求层，不在渲染期发生。
- 能从后端响应直接得到的展示值不再复制进 state；不保存可直接计算的派生值。
- Effect 只用于与外部系统同步（发请求、订阅、操作 DOM/第三方）。按 props/state 计算显示值、响应用户点击不需要 Effect；不要用多个 Effect 互相改 state 拼出业务流程。
- 远程请求由明确输入触发（关键参数变化、用户提交）；处理请求取消、过期响应和组件卸载，避免竞态与卸载后写 state。
- 非视图逻辑只有在出现独立责任或独立变化原因时才抽 Hook/模块；不为减少行数把表达式硬抽成更难读的 Hook。

## 3. 类型

- 前端类型是后端契约与读视图的**只读镜像**：外部响应、组件公共 props、状态模型、跨模块返回值都有明确类型。
- 不用 `any` 消编译错误，宁可 `unknown` 再收窄；不为炫技造维护者需要心算的条件/映射类型，能表达需求的最简类型优先。
- 用可辨识联合表达状态，避免多个可能互相矛盾的布尔位（如 `{ status: 'idle'|'loading'|'success'|'error' }` 优于 `isLoading`/`isSuccess`/`hasError` 并存）。
- 后端字段命名（snake/camel 混用）以契约为准，前端逐字镜像、不为「统一风格」改名。

## 4. 可访问性

- 操作元素用原生语义标签（`button`/`a`/`input`），不用可点击 `div`/`span` 冒充按钮；
- 输入控件有明确 label，图标按钮有可访问名称；
- 所有操作可键盘完成，焦点样式可见，焦点顺序合理；
- 异步结果、错误提示、弹层出现时焦点行为符合预期；
- 颜色不单独承担语义，状态同时有文字或图标。

## 5. 测试与工具

- 测行为不测实现：断言用户看到什么、能否发起操作、能否完成，覆盖 loading/401/404/5xx/empty/范围外各态、缺字段时如实显示「未取得」；不断言私有 state、Hook 调用次数或 DOM 层级。
- 用构造的视图模型测组件，不依赖真实后端。
- 确定性检查交给工具、不靠提示词硬记：类型检查（如 `tsc --noEmit`）、单测（如 `vitest`）、离线自包含检查；建议接入 ESLint + 可访问性插件（如 `eslint-plugin-jsx-a11y`）承接基础可访问性检查。

## 不做

- 不为固定的产品对象卡提前造通用卡片/表格/表单引擎或配置驱动系统——同一原因才变化的才抽象，长得像不算。
- 不在前端引入未清洗的 HTML（`dangerouslySetInnerHTML` 等）与任何密钥；演示/临时凭据只进内存，不入 storage/日志。
- 不套用与本栈无关的规范（他框架模块边界、跨产品设计令牌等）；需要时留通用参考、不进本文件。
